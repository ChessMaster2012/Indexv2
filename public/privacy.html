1. What Index collects

Optional account information

If a user creates an account, Index may process an email address for sign-in/recovery, a username, an optional display name, a password hash and salt for email/password accounts, and a Google account identifier when Google Sign-In is used.

Study/account data

Depending on the feature and whether the user is signed in, Index may store study progress, notes, study sets, rewards/progress, profile settings, and similar application state. Users should not put sensitive personal information into free-text fields.

Local context

The selected county or district is stored locally on the device so Index can display the appropriate local guidance. It is not used to claim that a district approved Index.

Live games

While a live game is running, temporary room codes, display names, questions, answers, scores, and related game state are processed by the game server. Live-room state is temporary and is not intended to be a student-record system.

AI Tutor messages

If the AI Tutor is used, the current conversation context is sent through the Index server to the configured third-party AI provider. Index does not intentionally send the user's account email, username, or profile information with the AI request.

Technical data

Normal connection information needed to deliver HTTP requests, protect the service, troubleshoot errors, and maintain security may be processed by the hosting infrastructure and service providers.

2. Data minimization

Index does not require a school name, grade, student ID, home address, or phone number to use county personalization. Index also does not require a student's school identity to use the core study features.

Do not enter sensitive information. Never put passwords, student ID numbers, home addresses, phone numbers, health information, financial information, or other sensitive personal information into study notes, study sets, game content, profile names, or AI messages.

3. AI processing and third parties

AI requests are proxied through the Index server rather than exposing a provider credential in browser code. The third-party AI provider receives the educational prompt/context necessary to generate the requested response. Third-party processing is subject to that provider's current terms and privacy practices; Index does not represent that a third-party provider is an MCPS-approved vendor.

Index's AI route is designed to avoid sending account identifiers and rejects several common forms of sensitive information before forwarding a prompt. This is a technical safeguard, not a guarantee that users can never enter sensitive information.

School-use note: Formal use of Index with student data remains subject to the applicable school district's review, privacy, security, accessibility, contracting, and consent requirements.

4. Storage and retention

Signed-in account data can persist in the configured database so progress can follow a user across devices. Browser-only study data remains in the browser until it is cleared or the relevant feature removes it. Temporary live-game state is held only while the game service needs it and is periodically expired by the server.

Index does not intentionally retain AI chat transcripts as an account history. The third-party AI provider may process requests according to its own current policies.

5. Account deletion

A signed-in user can use Delete account in the account controls. The server deletes the user's account row and saved account state from the primary account database and invalidates the active session. Index also clears the application-managed browser data used for the account, including saved study data and local context. Other browser data outside Index's managed storage may remain until the browser or user removes it.

If a deletion request cannot be completed because the service is temporarily unavailable, the application reports the failure instead of claiming that deletion succeeded.

6. Security

Production traffic is served over HTTPS. Email/password credentials are stored using a password hash and salt rather than plaintext passwords. Session cookies are HttpOnly, use SameSite protection, and use Secure in production. Server-side security headers and input validation are used where practical. No internet service can guarantee absolute security.

7. Children's and student privacy

Index is designed to minimize the information needed from students. It does not intentionally request sensitive student records. Because Index is not automatically approved by a school district, users should follow their district's current rules and should not use Index with school-controlled student information unless the applicable district has authorized that use.

8. District review and approval

This policy does not claim FERPA, COPPA, MODPA, Maryland Education Article, MCPS, or other district approval or certification. A district may require a privacy review, data-sharing agreement, parental consent, security review, accessibility review, or other conditions before student use.

9. Changes and contact

This policy may be updated as Index changes. The effective date is shown at the top of this page. For project issues or review documentation, use the Index Contact page. Do not publish sensitive student information in public issue trackers.

Index is an independent educational project and is not affiliated with or endorsed by any school district.
